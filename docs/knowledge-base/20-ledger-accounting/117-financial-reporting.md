# Financial Reporting

**Status:** STABLE (report inventory) — one report is a confirmed stub; all reports inherit the underlying ledger-integrity gaps documented elsewhere in this category.

| Reconciliation report | `GET /admin/finance/reconciliation` | Runs against mock data, not live gateway data (`PO-CRIT-02`) |

## The report-integrity caveat that applies to every row above

Every report in this table is generated by summarizing journal entries — and per [`113-ledger-invariants.md`](113-ledger-invariants.md), the underlying entries are neither guaranteed to balance (debit=credit unvalidated) nor guaranteed to exist for every real financial event (the missing `loan.created` gap means most loans have no entries at all). **This means every report above should currently be treated as illustrative of the intended reporting capability, not as a source of truth for actual financial decision-making**, until the invariant-enforcement and event-publishing gaps are closed. This is the single most important caveat in the entire Ledger & Accounting documentation category — Finance leadership should be explicitly briefed on it before relying on any dashboard number for a real decision.
